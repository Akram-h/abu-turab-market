# منصة الهمام التعليمية — الحزمة الكاملة (ويب + أندرويد + iOS)

كل شيء هنا يعمل على **خادم واحد**: الويب (PWA قابل للتثبيت) وتطبيقا الأندرويد وiOS يتصلان بنفس الخادم ونفس البيانات. كل مدرسة معزولة عن غيرها، والصلاحيات تُفرض في الخادم.

| المجلد | ما فيه |
|---|---|
| `server/` | الخادم + نسخة الويب (PWA) + ملفات النشر (Render / Docker / VPS) + تشغيل محلي بأيقونة لويندوز |
| `mobile/` | مشروع Capacitor جاهز لتوليد تطبيق **أندرويد (AAB/APK)** و**iOS (IPA)** |
| `store/` | أيقونة 512، صورة الميزات، لقطات شاشة (أندرويد / آيفون 6.7" / آيباد 12.9")، نصوص عربية وإنجليزية، سياسة الخصوصية، إجابات نماذج المتاجر |
| `samples/` | ملفا إكسل نموذجيان: الطلاب والمعلمين |

## الترتيب الصحيح (لا تقلبه)
1. **انشر الخادم** على الإنترنت ← تحصل على رابط HTTPS. (الويب يعمل فور هذه الخطوة ويُثبَّت من المتصفح.)
2. **ابنِ تطبيق الأندرويد** مضبوطاً على هذا الرابط.
3. **ابنِ تطبيق iOS** (يحتاج جهاز Mac).
4. ارفعهما إلى المتجرين.

> التطبيقان يحملان الواجهة داخلهما ويتصلان بالخادم عبر الرابط الذي تضبطه في الخطوة 2/3، فلا يعملان بدون خادم منشور.

## الخطوة 1 — نشر الخادم والويب
التفاصيل الكاملة في `server/SERVER-README.md`. الخلاصة (مجاني):
1. قاعدة بيانات مجانية من **neon.tech** ← انسخ `DATABASE_URL`.
2. ارفع محتويات مجلد `server/` إلى مستودع **GitHub**.
3. في **render.com**: New ← Blueprint (يقرأ `render.yaml`)، وأضف المتغيرات: `DATABASE_URL` و`OWNER_USER` و`OWNER_PASS` (حسابك كمسؤول نظام، كلمة المرور 6 أحرف فأكثر).
4. افتح الرابط وسجّل الدخول، ثم أضف المدرسة وحساب مديرها من «المدارس».

للاستعمال الجدي: خادم VPS مع `docker compose` (HTTPS تلقائي ونسخ احتياطي يومي) كما في `SERVER-README.md`.
**تجربة سريعة على حاسبتك (ويندوز):** ثبّت Node.js ثم اضغط مرتين على `server/make-desktop-icon.bat` ثم الأيقونة.

**تثبيت الويب كتطبيق:** أندرويد وويندوز (Chrome/Edge) ← زر «تثبيت التطبيق»؛ آيفون (Safari) ← مشاركة ← «إضافة إلى الشاشة الرئيسية».

## الخطوة 2 — تطبيق أندرويد
**المتطلبات:** Node.js 20+، JDK 17، Android Studio. حساب Google Play (رسم تسجيل لمرة واحدة).
```
cd mobile
npm install
node scripts/prepare.js https://رابط-خادمك          # يجهّز www ويضبط عنوان الخادم
npx cap add android
npx @capacitor/assets generate --android            # الأيقونات وشاشة البداية من مجلد assets
npx cap sync android
npx cap open android                                # يفتح Android Studio
```
في Android Studio: شغّل على هاتفك للتجربة، ثم **Build ← Generate Signed App Bundle (AAB)**؛ أنشئ مفتاح توقيع **واحتفظ به وبكلمة مروره** (بدونه لا تستطيع تحديث التطبيق). ارفع الـ AAB في Play Console.
- معرّف التطبيق `iq.alhamam.platform` (في `capacitor.config.json`). غيّره **قبل** أول نشر إن أردت، فلا يمكن تغييره بعده.
- تحقق في Play Console من **مستوى API المطلوب (target API)**؛ حزم Capacitor مضبوطة على «أحدث إصدار»، وإن اشتكى المتجر حدّثها `npm update`.
- مواد المتجر: `store/` (الأيقونة 512، صورة الميزات، لقطات `android/`، النصوص، `store-forms.md` لنموذج Data safety).

## الخطوة 3 — تطبيق iOS
**المتطلبات:** جهاز **Mac** مع Xcode، وحساب **Apple Developer** (رسم سنوي). بدون Mac استعمل خدمة Mac سحابية أو CI (Codemagic / GitHub Actions macOS).
```
cd mobile
npm install
node scripts/prepare.js https://رابط-خادمك
npx cap add ios
npx @capacitor/assets generate --ios
npx cap sync ios
npx cap open ios
```
في Xcode: اختر **Team** وتأكد من **Bundle Identifier** ثم جرّب على جهاز، ثم **Product ← Archive ← Distribute App ← App Store Connect**. إن طلب CocoaPods: `brew install cocoapods` ثم أعد `npx cap sync ios`.
- في App Store Connect: لقطات `store/screenshots/iphone` (6.7") و`ipad` (12.9") إن كان التطبيق يدعم الآيباد (أو اقصره على الآيفون من إعدادات Xcode)، سياسة الخصوصية، **حساب ولي أمر تجريبي فعّال** في خانة ملاحظات المراجعة (القالب في `store/store-forms.md`).
- **تنبيه صريح:** Apple قد ترفض تطبيقاً تراه «موقعاً معبّأ». هذا التطبيق يحمل واجهته داخل الحزمة ويستعمل المشاركة الأصلية وزر الرجوع، وهذا يحسّن الفرصة لكنه لا يضمن القبول، وقد تطلب Apple تعديلات.

## بعد النشر
- **تغيير البيانات** (طلاب، درجات…) لا يحتاج تحديث التطبيق: تُحفظ على الخادم.
- **تغيير تصميم الواجهة** يظهر فوراً في الويب؛ أما تطبيقا الجوال فيحتاجان إعادة بناء: `cd mobile && npm run sync` ثم إصدار جديد في المتجر.
- لتغيير الخادم (نطاق جديد) أعد `node scripts/prepare.js https://الجديد` ثم `npx cap sync` وأصدر نسخة جديدة.

## ما اختُبر وما لم يُختبر (للأمانة)
| البند | الحالة |
|---|---|
| الخادم، الصلاحيات، عزل المدارس، رفض الهجمات المباشرة على الواجهة البرمجية، الحفظ بعد إعادة التشغيل | **اختُبر** آلياً (35 فحصاً) |
| واجهة الويب على شاشة جوال، التثبيت (PWA)، العمل دون اتصال للواجهة | **اختُبر** في متصفح تجريبي |
| التطبيق المجمَّع يتصل بالخادم من نطاق آخر (CORS)، المشاركة الأصلية، زر الرجوع، الطباعة | **اختُبر** بمحاكاة إضافات Capacitor (8 فحوص) |
| سكربت `prepare.js` (مسارات الخطأ والنجاح) | **اختُبر** |
| بناء ملفات AAB / APK / IPA وتشغيلها على هاتف حقيقي، مراجعة المتجرين | **لم يُختبر** (يتطلب Android Studio وXcode وحساباتك) |
| قاعدة PostgreSQL الحقيقية | **اختُبر المسار بمحاكاة فقط**؛ جرّبه ببيانات تجريبية أولاً |
| أزرار واتساب | تفتح المحادثة والرسالة جاهزة وأنت ترسل؛ الإرسال التلقائي يحتاج WhatsApp Business API |
| الدروس والكتب والفيديو | بروابط (لا رفع ملفات للخادم) |

لا أستطيع ضمان خلوّ أي برنامج من الأخطاء؛ لذلك جرّب بمدرسة تجريبية (طالبان، معلم، ولي أمر) قبل الاستعمال الفعلي، وأبلغني بأي سلوك غير متوقع لأصلحه.
